## 6. Read-only data API и исправление SSR

Новый lib/api/catalog.ts читает только published apartments + layouts(plan_path); не делает insert/update/delete/RPC. Query через TanStack с abortSignal; scope SQL/backend не изменяется. Type-check подтверждает relation projection без as never/as any.

При первом подключении нового hook eager import принятого lib/supabase.ts вызвал в Expo SSR `ReferenceError: window is not defined`: AsyncStorage/Auth инициализировались на сервере. Исправлено **в каталожных потребителях**, не в клиенте R1.2: API экспортирует Boolean env probe без Auth, fetchCatalog выполняет guard первым и затем лениво import('../supabase'). Hook не импортирует клиент и отключает запрос без env/в preview. lib/supabase.ts остался byte-for-byte неизменным.

Это решает текущий unconfigured SSR путь; hosted Supabase чтение и configured SSR/Auth пока не проверены. Дополнительные API/SQL server listeners и реальные credentials в этой UI-фазе не требуются и не добавлялись.

Metro также один раз завершился из-за existing NativeWind/Metro file-watcher (`addedFiles`). Причина диагностирована; на прежнем8081 переиспользован/перезапущен сервис, framework/runtime ports не менялись. Финальные screenshots имеют pageErrors=[]; исправления node_modules не выполнялись.

## Дополнение к финальному DOM-контролю

Применённые правила appllama-app-design-skill: одна акцентная палитра без AI-default styling; иерархия typography; полный цикл loading/empty/error/content; локальный ephemeral state + TanStack для server state; safe-area/scroll content padding; press targets минимум48; без декоративного motion. Параметры shadow, Ionicons, FlatList и тёмная палитра взяты **из пользовательской спецификации**, а не изменены ради стандартных предпочтений навыка. accessibility использован для role/label/state и проверки контраста; webapp-testing — для реального production route, загрузки assets и интерактивных действий. React-native-design skill из прежних сессий в текущей восстановленной копии отсутствует; его чтение/применение в R1.3 не заявляется.

Дополнительный реальный DOM-замер показал, что in-flow filter hit48 увеличил text-to-text header gaps до12/28 вместо8/24. Исправлено только расположение filter hit area (absolute относительно header row), размер48 и круг44 сохранены. Последний capture проверяет фактические gaps8/24 assertion, а не полагается лишь на margin values. Финальные screenshots и measurements.json пересняты после этого исправления; координаты в итоговом дополнении имеют приоритет над более ранними строками таблицы, если они сдвинулись.
